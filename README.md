# 오려둔 공책

PDF 강의자료에서 영역을 드래그하면 그 부분을 잘라 AI 정리를 받고,
원하면 그 자리에 한 줄 메모로 붙여두는 학습 도구.

---

## 실행

Node 18 이상이 필요합니다. 설치할 패키지는 없습니다.

두 가지 모드가 있고, **기본은 구독입니다.**
모드는 `CLAUDE_USE_API`로만 정해집니다 — `ANTHROPIC_API_KEY`가 환경에 있어도
그것만으로는 API 경로로 가지 않습니다. 돈이 나가는 쪽은 명시적으로 켜야 합니다.

### A. 구독으로 돌리기 (기본)

```bash
npm i -g @anthropic-ai/claude-code
claude auth login          # Pro/Max 계정으로 로그인
node server.js             # 아무것도 안 하면 이 모드
```

서버가 요청마다 `claude -p`를 실행해 답을 받아옵니다.
잘라낸 이미지는 임시 파일로 저장하고 그 경로를 프롬프트에 적어 주며, 응답 후 지웁니다.

- 장점: 토큰 요금이 따로 나가지 않음
- 단점: 호출마다 프로세스가 뜨므로 API보다 느림 (수 초)
- 확인 필요: `-p` 모드가 구독이 아니라 API로 과금된다는 제보가 있습니다.
  처음 몇 번 돌린 뒤 청구 대시보드를 꼭 확인하세요.

### B. API 키로 돌리기 (명시적으로 켤 때만)

```bash
export CLAUDE_USE_API=1                  # 이걸 켜야 API 경로로 갑니다
export ANTHROPIC_API_KEY=sk-ant-...      # PowerShell: $env:CLAUDE_USE_API="1"; $env:ANTHROPIC_API_KEY="sk-ant-..."
node server.js
```

- 장점: 빠르고 안정적, 배포 가능
- 단점: 호출당 요금

`CLAUDE_USE_API=1`을 켰는데 키가 없으면 서버를 죽이지 않고 구독 경로로 되돌린 뒤
시작 로그에 그 사실을 찍습니다. 수업 중에 오타 하나로 도구가 안 뜨는 쪽이 더 나쁘기 때문입니다.

지금 어느 모드인지는 두 군데에서 확인할 수 있습니다 — 서버 시작 로그의 `모드:` 줄,
그리고 `/api/ask` 응답의 `X-Capnote-Mode` 헤더와 본문 `mode` 필드(`"cli"` 또는 `"api"`).

브라우저에서 `http://localhost:5173`

VS Code에서는 `F5`로 바로 띄우고 싶으면 `.vscode/launch.json`을 만들어
`server.js`를 program으로 지정하면 됩니다.

## 데스크톱 앱으로 만들기

터미널 없이 아이콘을 눌러 켜는 형태로 만들려면:

```bash
npm i -D electron electron-builder
npm start        # 앱 창으로 실행 (개발 중 확인용)
npm run dist     # 설치파일 생성 → dist/ 폴더
```

`npm run dist`를 돌린 운영체제의 설치파일이 나옵니다.
Windows에서는 `.exe`, macOS에서는 `.dmg`, Linux에서는 `.AppImage`.

### 세 OS 것을 한 번에 (GitHub Actions)

macOS 설치파일은 macOS에서만 만들 수 있어서, 한 대로는 세 개를 다 못 만듭니다.
`.github/workflows/build-installers.yml`이 각 OS 러너에서 따로 빌드해 줍니다.

```bash
git tag v0.1.0
git push origin v0.1.0     # 세 OS 빌드 → Release에 첨부
```

태그 없이 동작만 확인하고 싶으면 Actions 탭에서 수동 실행(Run workflow)하면 됩니다.
이때는 Release를 만들지 않고 결과물을 Artifacts에만 올립니다.

빌드 도구(electron, electron-builder)는 워크플로가 버전을 박아 직접 받습니다.
`package.json`에 의존성을 넣지 않은 건 이 앱에 런타임 npm 의존성이 없기 때문입니다.

`main.js`가 하는 일은 세 가지뿐입니다 — 빈 포트를 찾아 `server.js`를 앱 안에서 띄우고,
그 주소를 창으로 열고, Claude Code CLI가 있는지 확인해 없으면 안내합니다.
`server.js`와 `public/`은 그대로 재사용하므로 `npm run web`으로 터미널에서 돌리던 방식도 계속 됩니다.

### 배포할 때 걸리는 것

- **코드 서명 없이 배포하면 경고가 뜹니다.** Windows는 SmartScreen 경고,
  macOS는 "확인되지 않은 개발자" 차단. 본인 컴퓨터에서 쓰거나 몇 명에게 나눠줄 때는
  "그래도 실행"으로 넘길 수 있고, 실제로 팔 단계가 되면 그때 서명을 사면 됩니다.
- **Claude Code CLI는 앱에 포함할 수 없습니다.** 각 사용자가 직접 설치하고
  자기 계정으로 로그인해야 합니다. 앱은 확인과 안내까지만 합니다.
- **용량이 100MB를 넘습니다.** Electron이 브라우저를 통째로 안고 가기 때문입니다.
  더 가볍게 하려면 Tauri로 옮겨야 하는데, 그때는 `server.js`를 Rust로 다시 쓰거나
  사이드카로 붙여야 해서 일이 늘어납니다. 지금 단계에서는 Electron이 맞습니다.

### 데스크톱이 되면 풀리는 것

브라우저 안에서는 막혀 있던 것들이 열립니다.

- PDF 파일 경로를 기억해 다음에 켤 때 **자동으로 다시 열기**
- 노트를 브라우저 저장소가 아니라 **폴더에 파일로** 저장 (백업·git·MCP 연결에 유리)
- 전역 단축키로 앱을 불러오기

## 태블릿(안드로이드)에서 쓰기

안드로이드에서는 Claude Code가 돌지 않습니다. 그래서 **태블릿 앱은 정리를 PC에
부탁하고, PC가 늘 하던 대로 구독(`claude -p`)으로 받아 넘깁니다.** 추가 요금이 없습니다.
대신 그동안 PC가 켜져 있어야 합니다(잠자기 끄기).

**거리는 상관없습니다.** 같은 와이파이면 PC의 와이파이 주소로, 멀리 있으면
[Tailscale](https://tailscale.com)(무료) 주소(`100.x.x.x`)로 닿습니다. PC와 태블릿에
Tailscale을 깔고 같은 계정으로 로그인하면, 집 PC에 강의실 태블릿이 같은 망처럼 붙습니다.
오가는 내용도 Tailscale이 암호화합니다. 정리 한 번에 걸리는 시간은 대부분 모델이 생각하는
시간이라 멀어서 느려지는 것은 1초도 안 됩니다.

### 쓰는 법

1. PC에서 오려둔 공책을 켜고 위 줄 **상태 칩**(`Opus 5.5 · 보통`)을 누릅니다.
   아래에 **연결 코드**(8글자)와 이 PC의 주소가 나옵니다.
   처음 켤 때 Windows·macOS가 "들어오는 연결을 허용할까요?"를 물으면 허용하세요.
2. 태블릿에 APK를 깝니다. 설치파일 빌드의 Artifacts에 `오려둔 공책-<버전>.apk`가 있습니다.
   "출처를 알 수 없는 앱 설치"를 한 번 허용해야 합니다.
3. 태블릿 앱의 상태 칩(`PC 연결 필요`)을 눌러 PC 주소와 연결 코드를 넣고 `연결`.
   칩이 `Opus 5.5 · 보통`으로 바뀌면 끝입니다. 다음부터는 기억합니다.

### 연결 코드를 두는 까닭

태블릿에서 부를 수 있게 PC가 바깥 연결을 받다 보니, 같은 망의 다른 사람이 이 사람
구독으로 정리를 받아 가거나 PC에서 연 아무 웹페이지가 몰래 `/api/ask`를 부를 수
있게 됐습니다. 그래서 **이 PC 안의 앱 화면에서 온 요청만 코드 없이 통과**하고, 나머지는
코드가 맞아야 받습니다. 틀리면 잠깐 기다리게 해서 하나씩 대 보는 것을 늦춥니다.
PC에 터미널을 여는 로그인 단추와 코드 알려 주기는 PC 안에서만 됩니다.
코드는 `~/.capnote/pair.json`에 한 번 만들어 둡니다 — 켤 때마다 바뀌면 태블릿에 매번
다시 넣어야 합니다. 바꾸고 싶으면 그 파일을 지우고 앱을 다시 켜세요.

### 화면은 앱 안에, AI만 PC에

태블릿 앱은 PC 화면을 띄우는 게 아니라 `public/`을 앱 안에 담아 두고 AI만 PC에
묻습니다. 메모 저장소(IndexedDB)는 주소마다 따로 노는데, PC 화면을 띄우면 집(와이파이
주소)과 강의실(Tailscale 주소)에서 주소가 달라져 메모가 둘로 갈라집니다. 앱 안의 주소는
늘 같습니다. 그래서 PDF 보기·메모·형광펜·내보내기는 PC 없이도 되고, 정리·질문만 PC가
있어야 합니다.

### 손가락과 펜

- **한 손가락이나 펜**으로 끌면 오립니다(마우스와 같음).
- **두 손가락**으로 끌면 옮기고, 벌리거나 오므리면 쪽을 키우고 줄입니다. 두 번째 손가락이
  닿는 순간 그리던 오리기 상자는 버립니다 — 확대하려다 엉뚱한 곳이 오려지면 안 됩니다.
- **두 번 톡** 하면 그 자리에 직접 쓰는 메모가 생깁니다(더블클릭과 같음).
- 화면 전체 확대는 막았습니다. 두 손가락이 정리 칸에 닿으면 앱 전체가 확대되어 단추가
  화면 밖으로 밀려났습니다.
- 세로로 들면(폭 820px 이하) 정리 칸이 아래로 내려갑니다. 손가락 기기에서는 위 줄의
  확대·축소와 ←/→ 단추를 뺍니다 — 두 손가락과 쪽 양옆 큰 화살표가 같은 일을 합니다.
  그래서 768px 폭에서도 위 줄이 한 줄에 들어갑니다.
- 내보내기는 다운로드 폴더에 저장합니다. 웹뷰는 blob 주소를 내려받지 못해서 앱이
  조각으로 받아 씁니다.

### 안드로이드 껍데기

`android/`는 라이브러리 없는 웹뷰 하나입니다(Java, androidx도 안 씀). 화면 파일은
`public/`을 그대로 담아 가므로 복사본이 없습니다. 버전은 `package.json`에서 읽습니다.
서명 키(`android/capnote.keystore`)를 저장소에 둔 것은 일부러입니다 — 빌드마다 키가
바뀌면 새 버전을 덮어 깔 수 없어 지우고 다시 깔아야 하고, 지우면 태블릿의 메모가 같이
사라집니다. 직접 깔아 쓰는 앱이라 이걸로 충분하고, 스토어에 올린다면 키를 바꿔야 합니다.
빌드는 GitHub Actions(`안드로이드 APK 빌드`, 그리고 `설치파일 빌드`)에서 합니다.

## 구조

```
server.js            정적 서비스 + /api/ask 프록시 (키는 여기서만 쓰임)
public/index.html    앱 전체 (화면, 선택, 카드, 메모, 내보내기)
public/storage.js    IndexedDB 저장소 (Claude 아티팩트의 window.storage 대체)
main.js              데스크톱(Electron) 껍데기
android/             태블릿(안드로이드) 껍데기 — public/을 그대로 담는 웹뷰
```

파일이 세 개뿐이고 빌드 단계가 없습니다.
`public/index.html` 하나만 열면 앱 전체가 보입니다.

## Claude 아티팩트 버전에서 바뀐 것

| | 아티팩트 | 여기 |
|---|---|---|
| AI 호출 | 키 없이 바로 | `/api/ask` 프록시 경유, 키 필요 |
| 저장 | `window.storage` | IndexedDB (`storage.js`) |
| 실행 | 대화 옆 창 | `node server.js` |

`storage.js`가 `window.storage`와 **똑같은 모양**의 인터페이스를 제공하므로,
앱 코드는 저장 부분을 한 줄도 고치지 않았습니다.

## 메모는 어디에 있나

브라우저 안 **IndexedDB**입니다 — 데이터베이스 `capnote`, 저장소 `kv`.
서버로도 클라우드로도 나가지 않습니다. 열쇠는 이렇게 생겼습니다.

```
capnote:<파일이름>:<파일크기>:index      그 자료의 카드 번호 목록
capnote:<파일이름>:<파일크기>:card:<id>  카드 하나 (메모 글, 자리, 글자 크기…)
capnote:<파일이름>:<파일크기>:marks      형광펜·테두리
```

앞부분(`파일이름:파일크기`)이 **자료를 가리키는 이름표**입니다. 파일을 열 때마다
그 자리에서 다시 만들어 내므로, 같은 파일을 다시 열면 아무것도 고르지 않아도
저장해 둔 메모가 그대로 올라옵니다. 무작위 번호를 쓰면 열 때마다 새 자료가 되어
버립니다. 파일 이름을 바꾸거나 파일이 조금이라도 달라지면 **다른 자료로 봅니다** —
내용을 통째로 읽어 지문을 뜨면 668쪽짜리에서는 여는 데만 한참 걸립니다.

브라우저 저장소라 **시크릿 창, 다른 브라우저, 사이트 데이터 지우기**로는 사라집니다.
오래 두고 볼 것은 `페이지 추출`로 내보내 두세요 — 그 파일에는 카드가 함께 적혀
있어서, 다시 이 앱으로 열면 메모를 되살려 이어 고칠 수 있습니다.

글자 크기·한 쪽/두 쪽·대화창 폭처럼 자료와 상관없는 설정만 `localStorage`
(`capnote:memofs`, `capnote:spread`, `capnote:noteswidth`, `capnote:nsent`)에 둡니다.

## 한 쪽 / 두 쪽 보기

위 줄의 `한 쪽`을 누르면 두 쪽이 나란히 펼쳐집니다. 책은 원래 펼쳐 보는 것이라
교재에는 이쪽이 낫고, 슬라이드는 한 장씩 크게 보는 편이 낫습니다. 자료를 바꿔도
고른 대로 쓰게 브라우저에 적어 둡니다.

메모·형광펜·오려내기는 모두 "쪽 안에서 0~1" 좌표로 적어 두므로, 화면에 두 쪽이
있으면 어느 쪽의 좌표인지 가려야 합니다. 그래서 **자리(slot)** 를 둡니다 — 보이는
쪽마다 `{쪽 번호, 층 안에서의 자리}`를 적어 두고 그릴 때도 집을 때도 그 자리를
거칩니다. 한 쪽 보기는 자리가 하나뿐인 두 쪽 보기일 뿐이라 코드가 갈라지지 않습니다.

## 대화창 폭과 "PDF만"

오른쪽 대화창은 **가장자리를 끌어** 폭을 바꿉니다. 자료마다 읽기 좋은 폭이 달라서
(슬라이드는 넓게, 교재는 좁게) 하나로 못 박기 어렵습니다. 260px부터 창의 60%까지만
움직이며 — 그 밖으로 가면 한쪽이 못 쓰게 됩니다 — 정한 폭은 브라우저에 적어 둡니다.
두 번 누르면 기본값으로 돌아옵니다. 폭이 바뀌면 쪽을 다시 맞춰 그립니다.

위 줄의 `PDF만`은 위 줄·대화창·아래 줄을 숨기고 **전체화면**으로 들어갑니다. 수업
중에는 화면에 자료만 있는 편이 낫기 때문입니다. `Esc`나 떠 있는 `PDF만 끄기`로
나옵니다. 브라우저가 전체화면을 거절해도(권한·정책) 숨기는 것까지는 되게 두 가지를
따로 다룹니다.

`[5] 문장으로 정리`처럼 **문장 수를 직접 정할** 수 있습니다. "자세히"와 "짧게" 사이의
눈금이 대목마다 다르기 때문입니다. 정한 숫자는 기억해 두고, 자동 넣기에도 같이 씁니다.

## 그림에 표시하기

카드의 `그림에 표시`를 누르면 오려낸 그림 위에 화살표·동그라미·상자와 이름표를
얹습니다. **쪽 위 그 자리**에도 겹쳐 보이고, 썸네일·정리 PDF·페이지 추출 PDF에도
그대로 나갑니다. 다시 열어도 남아 있고, `표시 지우기`로 걷어낼 수 있습니다.

`자동 넣기` 팝업의 **오린 그림에 화살표·이름표 자동 표시**를 켜면 오려낼 때마다
알아서 표시합니다. 자동 넣기(무엇으로 정리할지)와는 따로 켜고 끕니다 — 자동 넣기가
꺼져 있어도 돕니다. 정리를 기다리지 않고 오리자마자 같이 시작하고, 글만 오린 것은
조용히 건너뜁니다. 이 설정은 기억해 둡니다(취향이라서). 켜 두면 위 줄 단추에
`· 그림`이 붙습니다.

**모델은 그림을 못 그립니다. 좌표를 받아서 우리가 그립니다.** 정확도가 전부라
세 가지를 합니다.

1. **격자를 얹어 보낸다.** 흐린 좌표 격자(5칸마다 선, 10칸마다 숫자, 0~100)를
   그림에 얹어 보내면 눈금을 읽고 답합니다. 그냥 "여기를 가리켜"라고 하면 크게
   빗나갑니다.
2. **한 번 더 확인한다.** 받은 표시를 격자 그림에 그려 다시 보여 주고 틀린 것만
   고치게 합니다. 빈 그림에 좌표를 찍는 것보다, 그려진 화살표가 맞는지 따지는
   것을 훨씬 잘합니다. 짚을 수 없는 것은 빼게 합니다 — 틀린 화살표는 없는 것보다
   나쁩니다.
3. **이름표 자리는 우리가 잡는다.** 모델에게 "빈 곳에 놓아라"라고 시키면 근육
   이름 글자 위나 그림 한가운데에 얹어 정작 봐야 할 그림을 가립니다. 빈 곳은 물을
   것 없이 화소를 세면 압니다. 그림을 100×100칸으로 나눠 얼마나 찼는지 재고,
   가리키는 곳 둘레를 거리·방향별로 훑어 **그림을 가장 덜 덮는 자리**를 고릅니다.
   다른 이름표와 겹치는 자리, 다른 표시가 가리키는 곳을 덮는 자리는 피하고, 선끼리
   엇갈리거나 선이 그림을 길게 가로지르면 조금 비싸게 칩니다. 고른 자리는 %로
   저장해서 썸네일·쪽 위·PDF 어디서 그려도 같은 자리에 나옵니다.

그림이 잘 보이게 하는 것도 같이 합니다. 선은 가늘게 긋되 흰 테를 둘러 어떤 바탕
위에서도 보이게 하고, 선을 먼저 다 그은 뒤 이름표를 얹어 어떤 선도 이름표 글자를
지나가지 않게 합니다. 동그라미는 그림 짧은 변 기준으로 재서 둥글게 그립니다 —
가로·세로를 따로 쟀더니 넓게 오린 그림에서 옆으로 퍼진 타원이 그림 절반을 덮었습니다.

척수 단면도로 재 본 값:

| | 제자리를 짚은 표시 |
|---|---|
| 격자만 | 6개 중 3개 (가지 대신 갈라지는 곳, 뿌리 위 빈 곳을 가리킴 · 이름표 겹침) |
| 격자 촘촘히 + 확인 + 이름표 자리 | **5개 중 5개** |

손으로 그린 것보다 깔끔해야 할 이유가 있습니다. 본인이 그린 화살표는 그리면서
기억하지만, 앱이 그려 준 것은 알아볼 수 있어야만 쓸모가 있습니다.

## 메모마다 되묻기

카드에 `이 메모에서 추가로 질문하기` 빈칸이 있습니다. `더 자세히`는 한 번 누르면
끝이라 되물을 수가 없었습니다. 공부하다 막히는 데는 사람마다 다르고, 무엇을 더
물을지는 본인만 압니다.

물을 때 그 카드의 **오려낸 그림까지 같이** 보냅니다. 정리 글만 넘기면 원문에 있던
수치나 그림을 다시 볼 수 없어 답이 뭉툭해집니다. 앞서 주고받은 것도 셋까지 붙여
이어 묻는 말("그 중에 제일 자주 다치는 건?")이 통하게 합니다.

주고받은 것은 카드에 쌓이고 **정리 PDF·마크다운에도 같이 나갑니다.** 화면에서만
보이고 종이에 안 나오면 그때 가서 또 물어야 합니다. 종이에서는 물음을 파랑 굵게로
띄워 정리 본문과 섞이지 않게 합니다.

치던 글은 카드에 잠깐 담아 둡니다(`card.draft`). 다른 카드가 끝나면서 목록을 다시
그려도 날아가지 않아야 하기 때문인데, 저장소에는 넣지 않습니다 — 남길 것이 아닙니다.

## 쪽 위에 얹히는 단추는 어둡게

`테두리 빼기`·형광펜 지우기(×)는 어두운 차림입니다. 밝은 차림으로 바꾸면서 이것들도
흰 단추가 됐는데, **PDF 쪽도 흰 종이라** 테두리 한 올만 남아 거의 안 보였습니다.
누르지 못하니 작동하지 않는 것으로 보입니다. 쪽 위에 놓이는 것은 쪽과 달라야 합니다.

## 메모를 얼마나 풀어 쓸지

`자동 넣기` 안에서 **짧게 · 보통 · 자세히** 중에 고릅니다. 기본은 보통입니다.

| | 줄 수 | 한 줄 |
|---|---|---|
| 짧게 | 3~4줄 | 25자 안팎, 핵심 낱말 위주 |
| **보통** | 4~6줄 | 40자 안팎, **완결된 문장** |
| 자세히 | 6~10줄 | 45자 안팎, 왜 그런지·어떤 조건인지까지 |

전에는 `각 줄 28자 이내로 끊어라`를 시켰습니다. 글자 수를 좁게 묶어 두면 모델이
문장을 포기하고 이렇게 답합니다.

```
정상보행: 입각기60%/유각기40%
2장 보행분석 핵심 수치
```

붙이는 순간에는 알아보지만, 일주일 뒤에 그 줄만 보면 무슨 말인지 모릅니다.
메모는 본문을 다시 읽지 않으려고 붙이는 것인데 그러면 붙인 뜻이 없습니다.
그래서 줄을 길게 열어 주고, 무엇보다 **"명사만 늘어놓거나 새 줄임말을 만들지 말고
읽어서 뜻이 통하는 문장으로"** 를 시킵니다.

규격은 `memoSpec()` 한 군데서 만듭니다. 오려내기·쪽 전체 정리·답 줄이기 세 군데가
같은 말을 따로 적고 있었는데, 그러면 한쪽만 고치고 맙니다.

바꾸면 **다음에 정리하는 것부터** 따라갑니다. 이미 붙여 둔 메모는 건드리지
않습니다 — 고쳐 놓은 걸 덮으면 안 됩니다.

## 메모 상자 크기

**접는 자리는 글이 정하고, 폭이 따라옵니다.** 반대로 하면 — 상자 폭을 190pt로
못 박아 두고 거기 맞춰 접으면 — `조직을`이 `조 / 직을`로 갈라지고, 한 문장이
애매하게 두 줄이 되어 오른쪽은 늘 비고, 짧은 메모도 같은 폭을 차지합니다.

그래서 **띄어쓰기 자리에서만** 접습니다. 한글은 글자 사이 아무 데서나 접어도
규칙에는 맞지만 읽다가 걸립니다. 한 어절이 상자보다 길 때만(긴 영어 낱말 따위)
어쩔 수 없이 쪼갭니다.

폭은 문장마다 따로 잽니다 — (1) 넓게 잡아 줄 수를 가장 적게 만들고, (2) 그 줄 수를
지키는 선에서 폭을 끝까지 줄입니다. (2)는 폭을 아끼려는 것이기도 하지만 무엇보다
줄을 고르게 만듭니다. 그냥 접으면 마지막 줄에 한 어절만 남습니다.

```
… 기도 확보가        전신마취는 의식·통증·움직임을
필요하다        →    모두 없애고 기도 확보가 필요하다
```

문장마다 따로 재야 긴 문장 하나 때문에 짧은 문장들까지 끌려가지 않습니다.
"상자 넓이가 가장 작은 폭"을 고르면 안 됩니다 — 글 넓이는 어차피 같아서 좁고 긴
탑이 뽑힙니다. 자료를 가리는 건 높이 쪽입니다.

고치는 중에는 상자를 좁히지 않습니다. 글칸 아래에 저장·빼기·글자 크기 단추가
들어가야 하기 때문입니다. 대신 치는 동안 상자가 글을 따라 늘어납니다.

## 물어본 답을 쪽에 붙이기

답은 물어본 쪽에만 붙는 게 아닙니다. **전체 쪽**·**여러 쪽**으로 물으면 답 하나가
여러 쪽 이야기를 합니다. 그걸 통째로 한 쪽에 붙이면 정작 그 내용이 있는 쪽에는
아무것도 안 남습니다.

답에 `N쪽`을 밝히도록 시켜 두었으므로(이동 단추도 이 표시로 만듭니다), 같은 표시를
따라 잘라 **쪽마다 제 몫만** 붙입니다. 단추에도 어디로 가는지 적습니다 —
`1·2·3·4쪽에 나눠 붙이기`, 쪽이 많으면 `10곳(1–10쪽)에 나눠 붙이기`.

답이 짚은 쪽은 다 붙습니다. 상한은 서른 쪽인데, 이건 답이 쪽 번호를 마구 뿌릴 때
668쪽짜리가 메모로 덮이지 않게 두는 안전선이지 평소에 걸리는 값이 아닙니다
(답은 열 줄 남짓이라 짚는 쪽도 그만큼입니다).

붙일 때 **한 번 더 줄입니다.** 오려낸 것은 정리와 함께 "메모용 3~5줄"을 따로 받아
두지만 물어본 답에는 그게 없어서, 전에는 답을 통째로 붙였습니다 — 특히 대화는 답이
길어 메모가 쪽을 덮었습니다. 받을 때가 아니라 **붙일 때** 줄입니다(안 붙일 답까지 값을
치를 이유가 없습니다). 이미 메모만 한 길이면 부르지 않습니다.

줄일 때는 오려낸 것과 같은 JSON 꼴로 받습니다. 그냥 "줄여 달라"고 하면
`정리해드리면:` 같은 머리말이 먼저 오고 그게 메모에 그대로 남습니다. 줄 수와 길이는
받아 온 뒤 코드로도 막습니다 — 시켜 놓고 믿기만 하면 여섯 줄이 옵니다.

첫 쪽은 원래 카드가 맡고, 나머지 쪽은 **목록에 올리지 않는 메모**로 남깁니다.
쪽마다 카드가 하나씩 생기면 질문 하나가 목록을 다 채웁니다. 이 메모는 그 자리에서
`지우기`로 없앱니다.

`자동 넣기`가 켜져 있으면 단추를 누를 것도 없이 바로 붙습니다. 전에는 자동 넣기가
오려낸 것에만 걸려 있어서, 전체·여러 쪽으로 물으면 답은 오는데 쪽에는 아무것도
남지 않았습니다 — 한쪽만 자동이면 규칙이 아니라 예외입니다.

## 모든 쪽 정리

정리 목록 머리의 **모든 쪽 정리**를 누르면 범위와 방식을 정해 쪽마다 정리를
붙입니다. (`자동 넣기` 팝업 안에도 같은 것이 있습니다 — 거기에만 두었더니 아무도
못 찾았습니다. 쪽마다 정리를 붙이는 일이니 정리 목록 머리에 있는 게 맞습니다.) 쪽마다 AI를 한 번씩 부르므로 쪽수만큼 걸립니다 — 세 쪽씩 나란히 돌리고,
끝나는 대로 바로 붙이고, 언제든 멈출 수 있습니다(그때까지 붙인 것은 남습니다).
이미 정리해 둔 쪽은 건너뜁니다.

## 형광펜

상단에서 `형광펜`으로 바꾸고 그으면, 그은 영역 안의 **글자 줄에 맞춰** 띠가 붙습니다.
대충 그어도 반듯하게 나옵니다. 색은 셋(노랑·초록·분홍)이고 자국을 누르면 지워집니다.

글자 정보가 없는 스캔 PDF에서는 화면에 그려진 그림에서 어두운 가로줄을 찾아 맞춥니다
— 글자가 있는 줄만 어둡기 때문입니다. OCR이 아니라 줄 자리만 보는 것이라 가볍습니다.
내보낼 때는 PDF 표준 Highlight 주석으로 들어가므로 굿노트 등에서 형광펜으로 인식하고,
글자가 비쳐 보입니다.

정리 PDF에도 그은 대목이 항목으로 들어갑니다 — 그 자리를 앞뒤가 조금 보이게 잘라
띠까지 얹은 그림과, 띠에 걸친 원문을 함께 담습니다.

## 내보내기 — 주석과 굽기

메모·형광펜은 기본적으로 **PDF 주석**으로 들어갑니다. 그래야 이 파일을 다시 열어
메모를 옮기고 고칠 수 있습니다(카드 정보는 PDF 안 `Capnote` 항목에 같이 담깁니다).

`메모를 그림으로 굽기`는 **꺼진 채로 시작합니다.** 한동안 켜 둔 채로 뒀는데,
되돌릴 수 없는 쪽을 말없이 골라 주는 것이라 되돌렸습니다. 남에게 낼 파일일 때만
사람이 켜서 굽습니다.

다만 주석을 아예 그리지 않는 뷰어가 있어서, 그런 곳에서는 메모가 통째로 안 보입니다.
그때는 `메모를 그림으로 굽기`를 켜고 내보내면 메모·형광펜·테두리가 페이지 그림 자체에
그려져 어디서든 보입니다. 대신 구운 것은 지울 수 없어서 그 파일로는 다시 고칠 수 없고,
`Capnote` 항목도 넣지 않습니다 — 이어서 고칠 때는 원본을 열면 됩니다.

## 전체 쪽에서 찾기

쪽마다 원문을 뽑아 두고, 물음에 나온 말이 있는 쪽만 골라 보냅니다. 700쪽짜리 교재라도
관련 있는 쪽 몇 장만 가므로 빠르고, 뒤쪽에 있는 내용도 찾습니다.

통째로 보내던 때에는 예산(24만 자)이 차는 266쪽에서 끊겼고, 540쪽에 있는 내용을 물으면
"자료에 없다"는 답이 돌아왔습니다 — 실은 보내지도 않은 것이었습니다.

물음에 걸리는 말이 하나도 없으면(예: "이 자료 무슨 내용이야") 앞쪽부터 담습니다.
어느 쪽이든 무엇을 보고 답했는지 카드 위에 적어 둡니다.

한글 자료는 글꼴 인코딩이 `/UniKS-UTF16-H` 같은 "미리 정해진 CMap"인 일이 흔합니다.
pdf.js는 그 표를 따로 받아야 글자를 풀 수 있어서(`cMapUrl`), 안 주면 조용히 빈 글을
돌려줍니다 — 크롬에서는 잘 긁히는 자료가 여기서는 안 읽히던 이유입니다.

**그래도 스캔해서 만든 자료는 뽑을 글자가 없습니다.**
그때는 `여러 쪽`으로 범위(예: `120-135`)를 정해 물어보세요 — 그 쪽들을 그림으로 보내
눈으로 보고 답합니다. 그림은 무거워서 한 번에 여덟 쪽까지입니다. 그때는 그 사실을 알리고, 쪽으로 가서
`이 쪽`으로 물으시면 화면을 그림으로 보고 답합니다.

## 오려낸 그림의 화질

오려낼 때는 **화면에서 자르지 않고 원본에서 다시 그립니다**(`cropFromPdf`).
화면에서 자르면 축소해 놓고 오렸을 때 그 자리의 화소가 몇 개 없어 뭉갭니다.
원본에서 다시 그리면 배율과 상관이 없습니다.

담는 크기는 AI에 보내는 것 2000px, 카드 썸네일 1000px입니다. 썸네일이 560px이던
시절이 있는데 그건 정리 패널이 350px 고정이던 때의 값이고, 지금은 패널 폭을 끌어
늘릴 수 있습니다. 축소해 놓고 오리면 한 장에 담기는 내용도 많아집니다 — 둘 다
같은 결과로 나타납니다. 글자 하나에 돌아가는 화소가 줄어 흐려집니다.
카드 하나가 25KB에서 74KB로 늘지만, 안 보이는 그림은 저장해 둘 이유가 없습니다.

## 화질 — 줄여서 보면 흐린 것

A4 한 장을 다 보이게 줄이면 본문 글자가 화면에서 예닐곱 화소밖에 안 됩니다.
이건 그리는 방법의 문제가 아니라 그 크기의 문제입니다.

**더 촘촘히 그려 놓고 브라우저가 줄이게 하는 방법(수퍼샘플링)을 재 봤지만 더
나빴습니다.** pdf.js는 그릴 크기에 맞춰 글자 획을 다듬는데, 크게 그려서 브라우저가
줄이면 그 다듬은 것이 뭉개집니다. 화면 화소와 1:1로 그리는 지금이 가장 곱습니다.

실제로 흐렸던 건 다른 데 있었습니다 — 캔버스 화소 수 상한이 낮아서, 고해상도
화면에서 크게 볼 때 **화면 화소보다 성기게** 그려 놓고 브라우저가 늘리고 있었습니다
(2배 화면에서 1.33배로 그림). 상한을 올려 그 구간을 없앴습니다. 상한은 "느려서 못
쓸 때"만 걸려야 합니다.

크게 보고 싶으면 `PDF만`(전체화면)이나 대화창 폭을 줄여 자리를 넓히는 편이 낫습니다.

## 어느 모델이 답하나

구독 경로(`claude -p`)도 API 경로도 **`claude-opus-5-5`, effort `medium`** 으로 부릅니다.
전에는 구독 경로에 모델을 적지 않아 사람마다 Claude Code에 기본으로 잡아 둔 모델로
갔습니다. 같은 앱인데 결과가 갈렸습니다. 바꾸려면 `CAPNOTE_MODEL` · `CAPNOTE_EFFORT`.
지금 무엇으로 가는지는 위 줄 칩에 늘 적혀 있습니다(`Opus 5.5 · 보통`). 창이 좁으면 `Opus 5.5`만 남깁니다.
칩을 누르면 모델 이름과 생각 깊이를 그대로 보여 줍니다.
(`CLAUDE_`로 시작하던 이름은 Claude Code가 제 설정으로 이미 쓰는 경우가 있어 앱 설정이 말없이 덮였습니다. 그래서 앱 이름으로 바꿨습니다.)

effort를 medium으로 둔 것은 수업 중에 쓰는 도구라서입니다. 한 번 묻는 데 오래
걸리면 안 쓰게 됩니다. 지금 무엇으로 가는지는 서버를 켤 때 한 줄로 찍히고,
앱 위 줄의 `Claude 준비됨`에 마우스를 올려도 보입니다.

## 로컬 모델 — 클로드를 대신하는 게 아니라 길이 하나 더 있는 것

앱이 AI를 부를 때 지나는 곳은 `/api/ask` 한 군데뿐이고, 그 안에 길이 셋 있습니다.

```
1) claude -p          구독. 기본값
2) Anthropic API      CLAUDE_USE_API=1 일 때만
3) 로컬 모델(Ollama)   사람이 고를 때만
```

세 번째를 더한 것이지 앞의 둘을 지운 게 아닙니다. `public/index.html`은 어느 길로
가는지 알 필요가 없습니다 — 서버가 Anthropic 꼴(content 블록)을 Ollama 꼴로 옮겨
담습니다. **npm 패키지도 빌드 단계도 늘지 않았습니다.** HTTP로만 붙습니다.

### 스캔본 글자 읽기 (이게 본래 목적)

그림으로만 된 교재는 pdf.js가 글자를 못 뽑아 "전체 쪽에서 찾기"가 통째로 막혔습니다.
그럴 때 정리 카드에 `로컬로 글자 읽기`가 뜹니다. 쪽 그림을 로컬 모델에 보내 글자를
받아 적고, 자료별로 적어 둡니다(`capnote:<자료>:ocr:<쪽>`). 한 번 읽으면 다음에
열어도 그대로입니다 — 668쪽을 두 번 읽게 하면 아무도 안 씁니다.

한 쪽씩 보냅니다. 여러 장을 한꺼번에 물리면 램이 터지거나 통째로 느려집니다.
언제든 멈출 수 있고 그때까지 읽은 것은 남습니다.

**정리는 그대로 클로드가 합니다.** OCR은 "보이는 대로 옮겨 적기"라 작은 모델로도
되지만, 정리는 다릅니다. 각자 잘하는 일이 다릅니다.

### 정리도 로컬로 (고를 때만)

위 줄의 `클로드`를 누르면 `로컬`로 바뀝니다. 구독 없이 돌리거나 인터넷이 없을 때를
위한 선택지입니다. **로컬 모델이 하나도 없으면 이 단추는 아예 안 보입니다** —
눌러 봐야 실패하는 단추는 없는 것만 못합니다.

오려낸 그림이 같이 갈 때는 그림을 보는 모델로 보냅니다. 글만 읽는 모델에 그림을
물리면 말없이 무시하고 엉뚱한 답을 씁니다. 사람이 그렇게 하겠다고 고르는 건 되지만,
앱이 몰래 그러면 안 됩니다.

### 쓰려면

```
ollama serve
ollama pull qwen2.5vl        # 글자 읽기 (그림을 보는 모델)
ollama pull exaone3.5        # 정리 (한국어)
```

깔린 것 중에서 골라 씁니다. 이름을 못 박아 두면 "그 모델이 없습니다"만 반복하게
됩니다. 지정하려면 `CAPNOTE_LOCAL_MODEL` · `CAPNOTE_OCR_MODEL`, 주소를 바꾸려면
`CAPNOTE_OLLAMA`입니다. **Ollama가 없어도 앱은 지금까지와 똑같이 돕니다.**

## 화면 — Apple 디자인 가이드

색·글자·모서리·그림자를 Apple 가이드의 토큰으로 바꿨습니다.

여백은 **가이드 쪽으로 한 번 키웠습니다** — 위 줄 44→70px, 단추는 가이드의
button-dark-utility(9×15px), 패널·카드·바닥은 17px, 쪽이 놓이는 자리는 32px.
다만 80px(`{spacing.section}`)까지 가지는 않습니다. 그건 한 화면에 제품 하나를
놓는 마케팅 페이지의 값이고, 여기는 수업 중에 자료를 보는 화면입니다.

묻는 칸은 15px입니다. 가이드의 17px는 **읽는 글**의 값인데, 그 줄은 `이 쪽`·묻는
칸·`묻기` 셋이 자리를 나눠 쓰는 곳이라 17px로 두면 350px 패널에서 안내글이
`이 쪽에 ㄷ`처럼 잘립니다. 아래 단추들에는 `white-space: nowrap`을 겁니다 —
자리가 모자랄 때 `페이지 추출`이 글자 단위로 접혀 세로 세 줄이 됐습니다.

### 좁아지면 접지 말고 줄인다

한동안 `flex-wrap: wrap`으로 흘려 보냈습니다. 그러면 단추가 아랫줄로 내려가면서
**자리가 통째로 바뀝니다.** 늘 있던 데 없으면 눈으로 다시 찾아야 하고, 수업 중에
쓰는 도구에서 그게 제일 거슬립니다. 그래서 한 줄에 두고 크기로 맞춥니다.

- **위 줄**은 창 폭을 따라갑니다 — `clamp(11px, 0.92vw, 14px)` 꼴로 글자·여백이
  같이 줄어듭니다.
- **패널 안**은 창이 아니라 `--notes-w`를 따라가야 합니다.
  `clamp(11px, calc(var(--notes-w) * 0.038), 13px)`처럼 씁니다.
- 끝까지 줄여도 모자라면 **덜 중요한 글자부터 접습니다** — 버전, 상태 칩의 글
  (점만 남아도 색으로 압니다), `메모 가－`의 "메모". **단추를 없애지는 않습니다.**
  있던 것이 사라지면 고장 난 줄 압니다.
- 그래도 모자라면 위 줄만 가로로 밀어서 봅니다.

안내글도 짧게 고쳤습니다 — 어느 범위인지는 왼쪽 칩이 이미 말해 주는데 안내글에서
또 되뇌다 보니(`이 쪽에 대해 물어보기`) 잘렸습니다.

### 넘김 화살표는 쪽 위에 뜬다

전에는 `.stage`의 flex 자식이라 좌우로 **132px을 차지했습니다.** 자료를 보려고 만든
화면에서 자료가 그만큼 줄어드는 건 앞뒤가 바뀐 것입니다. 이제 띄워서 겹칩니다
(평소 28% 불투명, 가져가면 또렷).

기준은 `.stage`가 아니라 **`.main`** 입니다. `.stage`는 스크롤하는 칸이라 내용이
길면 화살표가 같이 밀려 내려갑니다 — `top: 42vh` 같은 어림수로 맞춰 두었던 이유이고,
그게 "살짝 아래"의 정체였습니다. `.main`을 기준으로 잡으면 `top: 50%`가 정확히
세로 한가운데입니다.

**띄우는 것만으로는 쪽이 커지지 않습니다.** `fitScale()`이 화살표 몫으로 132px을
미리 덜어 내고 있었습니다. 그걸 지워야 쪽이 그 자리를 씁니다 — 두 쪽 보기에서
자리의 81% → **97%**, 화살표는 쪽 위로 42px 겹칩니다.

```js
var flips = (46 + 20) * 2;          // 지웠다
var w = st.clientWidth - padX;      // 화살표는 쪽이 피해 줄 대상이 아니다
```

한 쪽 보기에서 쪽이 여전히 작다면 그건 화살표가 아니라 **높이**가 잡는 것입니다.
A4는 세로가 길어서 넓은 창에서도 높이가 먼저 찹니다.

### transform은 하나뿐이다

`button:active`의 `scale(0.95)`가 화살표를 세로 가운데에 붙들던 `translateY(-50%)`를
덮어써서, 누를 때마다 반 칸(22px) 아래로 떨어졌다 돌아왔습니다. 자리를 잡는 몫은
`--place`에 따로 두고 둘을 같이 씁니다.

```css
button:active:not(:disabled) { transform: var(--place, translate(0)) scale(0.95); }
.pageflip { --place: translateY(-50%); transform: var(--place); }
.bdel     { --place: translateX(-100%); transform: var(--place); }
```

### overflow는 팝업도 자른다

위 줄에 `overflow-x: auto`(넘침 대비)를 걸자 `자동 넣기` 팝업이 통째로 안 보이게
됐습니다. `overflow`가 `visible`이 아니면 그 안의 `absolute` 자식도 같이 잘립니다.
팝업은 창 기준(`fixed`)으로 띄우고, 자리는 열 때 단추를 재서 잡습니다.

그리고 그 팝업은 `.bar` 안에 있어서 **`.bar button`의 검은 단추 차림을 물려받고
있었습니다.** 흰 바탕 팝업에 검은 알약이 박히고 고른 항목은 흰 글씨라 아예 안
보였습니다 — "지금 뭐가 설정됐는지 모르겠다"의 정체입니다. 고른 항목은 이제
파랑으로 채웁니다(누를 수 있는 것은 전부 파랑이라는 규칙 그대로).

옮긴 것:

| | |
|---|---|
| 누를 수 있는 것 | 파랑 `#0066cc` 하나. 두 번째 강조색은 없음 |
| 형광펜·메모 노랑 | 그대로 — 꾸밈이 아니라 **내용**이라 강조색 규칙 밖 |
| 위 줄 | 순검정 global-nav. 이 앱에서 검정이 나오는 유일한 곳 |
| 바탕 | parchment `#f5f5f7`, 패널·카드는 흰색 |
| 단추 | 유틸 8px 모서리 / 누르는 것은 알약. 그 사이는 안 씀 |
| 누른 느낌 | `scale(0.95)` — 가이드가 정한 유일한 미세동작 |
| 그림자 | **쪽과 그 위 메모에만.** 단추·카드·패널에는 없음 |
| 떠 있는 것 | 그림자 대신 실선 한 올 + 흐린 유리(backdrop-blur) |
| 읽는 글 | 17px. 위 줄·단추는 14px |

가장 크게 바뀐 건 색이 하는 일입니다. 전에는 노랑 하나가 "누를 수 있다"와
"칠해 둔 자국"을 겸해서 둘이 구분되지 않았습니다. 이제 갈라져 있습니다.

## 알려진 제약

- **PDF 파일 자체는 저장하지 않습니다.** 카드와 메모만 저장하고,
  파일 이름 + 크기를 열쇠로 삼아 다시 붙입니다. 그래서 같은 PDF를 매번 열어야 합니다.
- **한글 폰트 문제로 PDF 내보내기의 메모는 이미지로 심습니다.**
  pdf-lib 표준 폰트에 한글이 없어서, 메모를 캔버스에 그린 뒤 PNG로 얹는 방식입니다.
  선택 가능한 텍스트가 필요해지면 한글 TTF를 embed하도록 바꿔야 합니다.
- **메모 자리는 자동으로 빈 곳을 찾습니다.** 오려낸 영역 오른쪽 → 왼쪽 → 아래 → 위 순으로
  보고, 다 막혔으면 페이지를 훑어 가장 가까운 여백에 놓습니다. 오려낸 그림과 다른 메모는
  절대 덮지 않고, 본문 글자는 되도록 피합니다. 빽빽해서 여백이 없는 슬라이드에서는
  글자를 조금 가릴 수 있는데, 그때도 오려낸 그림만은 지킵니다.
- **브라우저 안이라 다른 앱 화면은 잡을 수 없습니다.** 이건 우회가 아니라 벽입니다.
  굿노트 화면까지 잡으려면 안드로이드 앱이 필요합니다.
