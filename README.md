# 오려둔 공책

PDF 강의자료에서 영역을 드래그하면 그 부분을 잘라 AI 정리를 받고,
원하면 그 자리에 한 줄 메모로 붙여두는 학습 도구.

---

## 실행

Node 18 이상이 필요합니다. 설치할 패키지는 없습니다.

두 가지 모드가 있고, **기본은 구독입니다.**
모드는 `CLAUDE_USE_API`로만 정해집니다 — `ANTHROPIC_API_KEY`가 환경에 있어도
그것만으로는 API 경로로 가지 않습니다. 돈이 나가는 쪽은 명시적으로 켜야 합니다.

### A. 구독으로 돌리기 (기본)

```bash
npm i -g @anthropic-ai/claude-code
claude auth login          # Pro/Max 계정으로 로그인
node server.js             # 아무것도 안 하면 이 모드
```

서버가 요청마다 `claude -p`를 실행해 답을 받아옵니다.
잘라낸 이미지는 임시 파일로 저장하고 그 경로를 프롬프트에 적어 주며, 응답 후 지웁니다.

- 장점: 토큰 요금이 따로 나가지 않음
- 단점: 호출마다 프로세스가 뜨므로 API보다 느림 (수 초)
- 확인 필요: `-p` 모드가 구독이 아니라 API로 과금된다는 제보가 있습니다.
  처음 몇 번 돌린 뒤 청구 대시보드를 꼭 확인하세요.

### B. API 키로 돌리기 (명시적으로 켤 때만)

```bash
export CLAUDE_USE_API=1                  # 이걸 켜야 API 경로로 갑니다
export ANTHROPIC_API_KEY=sk-ant-...      # PowerShell: $env:CLAUDE_USE_API="1"; $env:ANTHROPIC_API_KEY="sk-ant-..."
node server.js
```

- 장점: 빠르고 안정적, 배포 가능
- 단점: 호출당 요금

`CLAUDE_USE_API=1`을 켰는데 키가 없으면 서버를 죽이지 않고 구독 경로로 되돌린 뒤
시작 로그에 그 사실을 찍습니다. 수업 중에 오타 하나로 도구가 안 뜨는 쪽이 더 나쁘기 때문입니다.

지금 어느 모드인지는 두 군데에서 확인할 수 있습니다 — 서버 시작 로그의 `모드:` 줄,
그리고 `/api/ask` 응답의 `X-Capnote-Mode` 헤더와 본문 `mode` 필드(`"cli"` 또는 `"api"`).

브라우저에서 `http://localhost:5173`

VS Code에서는 `F5`로 바로 띄우고 싶으면 `.vscode/launch.json`을 만들어
`server.js`를 program으로 지정하면 됩니다.

## 데스크톱 앱으로 만들기

터미널 없이 아이콘을 눌러 켜는 형태로 만들려면:

```bash
npm i -D electron electron-builder
npm start        # 앱 창으로 실행 (개발 중 확인용)
npm run dist     # 설치파일 생성 → dist/ 폴더
```

`npm run dist`를 돌린 운영체제의 설치파일이 나옵니다.
Windows에서는 `.exe`, macOS에서는 `.dmg`, Linux에서는 `.AppImage`.

### 세 OS 것을 한 번에 (GitHub Actions)

macOS 설치파일은 macOS에서만 만들 수 있어서, 한 대로는 세 개를 다 못 만듭니다.
`.github/workflows/build-installers.yml`이 각 OS 러너에서 따로 빌드해 줍니다.

```bash
git tag v0.1.0
git push origin v0.1.0     # 세 OS 빌드 → Release에 첨부
```

태그 없이 동작만 확인하고 싶으면 Actions 탭에서 수동 실행(Run workflow)하면 됩니다.
이때는 Release를 만들지 않고 결과물을 Artifacts에만 올립니다.

빌드 도구(electron, electron-builder)는 워크플로가 버전을 박아 직접 받습니다.
`package.json`에 의존성을 넣지 않은 건 이 앱에 런타임 npm 의존성이 없기 때문입니다.

`main.js`가 하는 일은 세 가지뿐입니다 — 빈 포트를 찾아 `server.js`를 앱 안에서 띄우고,
그 주소를 창으로 열고, Claude Code CLI가 있는지 확인해 없으면 안내합니다.
`server.js`와 `public/`은 그대로 재사용하므로 `npm run web`으로 터미널에서 돌리던 방식도 계속 됩니다.

### 배포할 때 걸리는 것

- **코드 서명 없이 배포하면 경고가 뜹니다.** Windows는 SmartScreen 경고,
  macOS는 "확인되지 않은 개발자" 차단. 본인 컴퓨터에서 쓰거나 몇 명에게 나눠줄 때는
  "그래도 실행"으로 넘길 수 있고, 실제로 팔 단계가 되면 그때 서명을 사면 됩니다.
- **Claude Code CLI는 앱에 포함할 수 없습니다.** 각 사용자가 직접 설치하고
  자기 계정으로 로그인해야 합니다. 앱은 확인과 안내까지만 합니다.
- **용량이 100MB를 넘습니다.** Electron이 브라우저를 통째로 안고 가기 때문입니다.
  더 가볍게 하려면 Tauri로 옮겨야 하는데, 그때는 `server.js`를 Rust로 다시 쓰거나
  사이드카로 붙여야 해서 일이 늘어납니다. 지금 단계에서는 Electron이 맞습니다.

### 데스크톱이 되면 풀리는 것

브라우저 안에서는 막혀 있던 것들이 열립니다.

- PDF 파일 경로를 기억해 다음에 켤 때 **자동으로 다시 열기**
- 노트를 브라우저 저장소가 아니라 **폴더에 파일로** 저장 (백업·git·MCP 연결에 유리)
- 전역 단축키로 앱을 불러오기

## 구조

```
server.js            정적 서비스 + /api/ask 프록시 (키는 여기서만 쓰임)
public/index.html    앱 전체 (화면, 선택, 카드, 메모, 내보내기)
public/storage.js    IndexedDB 저장소 (Claude 아티팩트의 window.storage 대체)
```

파일이 세 개뿐이고 빌드 단계가 없습니다.
`public/index.html` 하나만 열면 앱 전체가 보입니다.

## Claude 아티팩트 버전에서 바뀐 것

| | 아티팩트 | 여기 |
|---|---|---|
| AI 호출 | 키 없이 바로 | `/api/ask` 프록시 경유, 키 필요 |
| 저장 | `window.storage` | IndexedDB (`storage.js`) |
| 실행 | 대화 옆 창 | `node server.js` |

`storage.js`가 `window.storage`와 **똑같은 모양**의 인터페이스를 제공하므로,
앱 코드는 저장 부분을 한 줄도 고치지 않았습니다.

## 형광펜

상단에서 `형광펜`으로 바꾸고 그으면, 그은 영역 안의 **글자 줄에 맞춰** 띠가 붙습니다.
대충 그어도 반듯하게 나옵니다. 색은 셋(노랑·초록·분홍)이고 자국을 누르면 지워집니다.

글자 정보가 없는 스캔 PDF에서는 그은 자리를 그대로 칠합니다.
내보낼 때는 PDF 표준 Highlight 주석으로 들어가므로 굿노트 등에서 형광펜으로 인식하고,
글자가 비쳐 보입니다.

## 내보내기 — 주석과 굽기

메모·형광펜은 기본적으로 **PDF 주석**으로 들어갑니다. 그래야 이 파일을 다시 열어
메모를 옮기고 고칠 수 있습니다(카드 정보는 PDF 안 `Capnote` 항목에 같이 담깁니다).

다만 주석을 아예 그리지 않는 뷰어가 있어서, 그런 곳에서는 메모가 통째로 안 보입니다.
그때는 `메모를 그림으로 굽기`를 켜고 내보내면 메모·형광펜·테두리가 페이지 그림 자체에
그려져 어디서든 보입니다. 대신 구운 것은 지울 수 없어서 그 파일로는 다시 고칠 수 없고,
`Capnote` 항목도 넣지 않습니다 — 이어서 고칠 때는 원본을 열면 됩니다.

## 알려진 제약

- **PDF 파일 자체는 저장하지 않습니다.** 카드와 메모만 저장하고,
  파일 이름 + 크기를 열쇠로 삼아 다시 붙입니다. 그래서 같은 PDF를 매번 열어야 합니다.
- **한글 폰트 문제로 PDF 내보내기의 메모는 이미지로 심습니다.**
  pdf-lib 표준 폰트에 한글이 없어서, 메모를 캔버스에 그린 뒤 PNG로 얹는 방식입니다.
  선택 가능한 텍스트가 필요해지면 한글 TTF를 embed하도록 바꿔야 합니다.
- **메모 자리는 자동으로 빈 곳을 찾습니다.** 오려낸 영역 오른쪽 → 왼쪽 → 아래 → 위 순으로
  보고, 다 막혔으면 페이지를 훑어 가장 가까운 여백에 놓습니다. 오려낸 그림과 다른 메모는
  절대 덮지 않고, 본문 글자는 되도록 피합니다. 빽빽해서 여백이 없는 슬라이드에서는
  글자를 조금 가릴 수 있는데, 그때도 오려낸 그림만은 지킵니다.
- **브라우저 안이라 다른 앱 화면은 잡을 수 없습니다.** 이건 우회가 아니라 벽입니다.
  굿노트 화면까지 잡으려면 안드로이드 앱이 필요합니다.
